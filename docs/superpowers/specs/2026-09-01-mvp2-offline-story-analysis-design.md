# MVP2 Codex 离线小说分析设计

日期：2026-09-01  
状态：用户已批准

## 1. 目标

MVP2 面向单人本地项目。整本小说分析是一次性预处理工作，由 Codex 离线生成候选 `StoryMap`；项目只负责安全导入、严格校验、缓存和消费结果。项目运行时不通过 OpenRouter 分析整本小说，也不提供自动分块或分析重试。

OpenRouter 继续只服务于游戏过程中既有的即时生成能力。缺少小说分析时，项目明确报告缺失，不发起模型调用。

## 2. 范围

本阶段包含：

- 安全导入 TXT、MD、DOCX 小说并计算正文哈希；
- Codex 在项目外部推理后生成候选 `StoryMap` JSON；
- 本地命令对候选文件进行只读校验或原子导入；
- 按小说哈希、离线分析版本和 DLC 版本读取本地分析；
- 网页/API 展示 `ready`、`missing`、`invalid` 三种状态；
- 后续章节规划、会话和阅读器只消费已验证的离线分析。

本阶段不包含：

- 运行时整本小说 LLM 分析；
- 网页上传或编辑候选分析；
- 缺失分析时调用 OpenRouter；
- 自动修复候选文件；
- 分析阶段生成具体波形、强度或随机间隔；
- 视频、摄像头、麦克风、实时用户反应或人工情节点波形编辑。

## 3. 架构

数据流固定为：

1. `StorySourceLoader` 安全读取小说、规范化正文并计算源哈希。
2. Codex 根据原文生成候选 `StoryMap` JSON，写入被 Git 忽略的 `data/story_candidates/`。
3. 本地命令重新读取小说，不信任候选文件声明的哈希，并校验完整结构。
4. 校验成功后通过现有 `AnalysisStore` 原子写入被 Git 忽略的 `data/story_analysis/`。
5. 网页/API 按有效身份读取分析；只有 `ready` 状态可进入章节规划。
6. 任务 4 及后续逻辑使用稳定章节/场景记录生成运行时随机波形、强度和间隔。

保留 `StorySourceLoader`、`StoryMap`、`AnalysisKey` 和 `AnalysisStore`。现有 `StoryAnalyzer` 不再属于运行时或公共 API；其可复用验证逻辑应迁入边界清晰的离线导入组件，不再维护在线整本分析链路。

## 4. 身份与存储

正式分析身份由以下字段共同决定：

- `source_hash`：规范化小说正文的完整 SHA-256；
- `producer`：固定为 `codex-offline`，沿用现有 `AnalysisKey.model` 字段存储；
- `analysis_version`：固定初始值 `faithful-offline-v1`，沿用 `prompt_version` 字段存储；
- `dlc_version`：当前 DLC 配置的稳定版本标识。

正文、分析版本或 DLC 版本任一变化都产生新身份，不迁移或猜测复用旧分析。旧缓存可以留在本地，但不会被新身份命中。

候选目录与正式分析目录都必须位于仓库本地 `data/` 下、受既有重定向和原子写入保护，并由 Git 忽略。候选文件默认命名为 `<source_hash>.json`，允许保留供人工检查。

## 5. StoryMap 内容

每个章节和场景只保存：

- 基于完整源哈希和零基索引生成的稳定 ID；
- 原文起止字符偏移；
- 简体中文非空摘要；
- 有界场景节奏系数。

章节优先遵循原文明确标题。没有标题时，Codex 按完整剧情段落建立逻辑章节。场景按连续事件或自然情节变化切分，不按固定字数机械切分；极长连续事件可拆分。

章节必须从偏移 0 开始无缝、无重叠地覆盖全文；每章场景必须无缝、无重叠地覆盖该章。不得省略、重排或越过任何原文字符。分析不保存具体波形、强度和随机间隔，以保留运行时随机性。

## 6. 本地命令

提供同一离线导入工具的两个动作：

```text
python -m backend.story.import_analysis validate --source <小说路径> --map <候选JSON> --encoding auto
python -m backend.story.import_analysis import   --source <小说路径> --map <候选JSON> --encoding auto
```

`--encoding` 只接受 `auto`、`utf-8`、`gb18030`，语义与任务 1 一致。

`validate` 只读，不创建正式缓存。`import` 执行同一套校验，全部成功后才原子保存。命令输出源哈希、分析身份、章节/场景数量和目标状态，不输出小说正文。

## 7. 信任边界与校验

候选 JSON 是不可信输入。导入器必须：

- 严格解析 JSON，拒绝重复键、额外字段、异常深度和超过配置上限的文件；
- 从真实源文件重算哈希和正文长度；
- 拒绝候选文件中的哈希、ID或长度与真实源不一致；
- 拒绝章节/场景缺口、重叠、乱序、越界和空分区；
- 拒绝空白摘要、非法节奏值和不正确的稳定 ID；
- 复用 `AnalysisStore` 的目录约束、重定向防护、损坏隔离和原子替换；
- 在任何失败时不写入部分缓存，也不调用模型或自动修改候选文件。

校验错误应包含可定位的字段、章节或场景索引，但不得回显大段小说正文。

## 8. 运行时状态与 API

小说导入后的分析状态只有：

- `ready`：当前源哈希、分析版本和 DLC 版本存在可信缓存；
- `missing`：没有匹配缓存；
- `invalid`：匹配缓存存在但损坏、版本错误或无法安全读取。

删除原计划中的“开始分析”和“重试分析”运行时接口。保留或新增：小说导入、分析状态查询、章节列表、正文切片、章节计划和会话控制接口。

缺失分析返回稳定业务码 `analysis_missing`；无效分析返回 `analysis_invalid`。二者都不是 HTTP 500，也绝不触发 OpenRouter。只有 `ready` 状态允许创建章节计划。

## 9. 网页行为

网页显示小说名称、源哈希短标识、分析状态、分析版本和 DLC 版本。

- `ready`：显示章节并允许后续操作；
- `missing`：显示需由 Codex 生成候选文件并运行本地导入命令的提示；
- `invalid`：提示删除或隔离损坏分析并重新生成。

网页不增加候选文件上传器、分析编辑器、运行时分析按钮或自动重试。缺失分析时不显示可启动章节的控件。

## 10. 测试与验收

自动测试至少覆盖：

- 合法候选的 validate 与 import；
- 小说哈希、正文长度、ID 和分析身份不匹配；
- 正文、分析版本或 DLC 变化导致旧分析不命中；
- 章节/场景缺字、重叠、乱序、越界、空摘要和非法节奏；
- 重复字段、额外字段、超大、过深或畸形 JSON；
- 原子写入、损坏缓存隔离和目录重定向保护；
- API 的 `ready`、`missing`、`invalid` 状态；
- 缺失或无效分析时没有 OpenRouter 调用；
- 任务 1、2 和 MVP1 的全量回归。

人工验收只要求：Codex 为一份本地小说生成候选文件，命令成功导入，网页显示匹配章节。推送、标签和真实设备验收仍不在本轮自动授权范围内。

## 11. 对原计划的替代

原任务 3“整本小说在线分析与上下文降级”被本设计替代，不再进行第六轮在线错误分类修复。已完成的安全导入、稳定模型、缓存和通用验证继续使用；在线 `StoryAnalyzer` 及专用接口从运行时断开，确认无引用后删除其专用实现和测试。

后续任务顺序调整为：

1. 新任务 3：Codex 候选文件校验与离线导入；
2. 任务 4：基于离线 `StoryMap` 的完整章节忠实规划；
3. 任务 5：小说会话、暂停、恢复和存档；
4. 任务 6：离线分析状态及小说运行 API；
5. 任务 7：阅读器和缺失分析提示；
6. 任务 8：本地集成测试与发布门槛。

整个实现继续遵循 MVP 原则：不为未来的多人、通用用户或在线分析场景增加兼容层。
